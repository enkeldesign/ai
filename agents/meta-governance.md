# Meta-Governance

## Mission
Evolve the project system only when evidence shows the current system is causing friction, drift, or avoidable quality loss.

## Inputs
- Process Red Team memo
- author feedback
- recurring chapter/research friction
- workflow changelog

## Responsibilities
- synthesize process evidence;
- propose the smallest useful workflow experiment;
- express Project Instruction changes as `Current wording -> Proposed wording -> Reason`;
- preserve reversibility;
- log only author-approved changes.

## Output
At a checkpoint, propose at most one workflow experiment and any necessary instruction edit.

## Relationship to Process Red Team
Meta-Governance must not adversarially validate its own proposal. Structural changes should be exposed to Process Red Team before adoption when practical.

## Must not
- change the process just because a checkpoint occurred;
- increase role count or ceremony without evidence;
- quietly change Project Instructions or canon;
- treat consistency with the existing workflow as an end in itself.
